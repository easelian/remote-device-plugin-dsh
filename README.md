# Remote Device Hub for DeepSeek Harness

[中文](README.zh.md)

A DeepSeek Harness bundle that connects your authorized Linux and macOS devices
through [Remote Device Hub](https://mcp.easelian.com/mcp). It contributes:

- the Remote Device Hub MCP tools (`mcp__remote-device-hub__*`);
- a `remote-device-hub` skill that explains safe device workflows;
- an approval gate before file writes, commands, process control, and other
  device-mutating tools when the profile has an approval channel.

It is the DSH counterpart of the VS Code and Codex Remote Device Hub plugins.
No system Node.js is required: the bridge runs on the DSH runtime itself.

## Requirements

- DeepSeek Harness `0.2.0` or newer.
- Access to one distribution channel: the private Git repository (SSH key plus
  `github.com` in `~/.ssh/known_hosts`), the public Git repository, the npm
  package, or a configured plugin-market index.
- A browser for the first Remote Device Hub sign-in.
- Permission to install a bundle in the current DSH profile. The plugin manager
  asks for `danger-full-access` approval, because bundles add Host code.

## Install

### Web UI

1. Open **Plugins** in the DSH sidebar.
2. Choose to install a bundle from Git and enter:

   ```text
   git+ssh://git@github.com/be-one-click/remote-device-plugin-dsh.git
   ```

3. Keep the bundle enabled. Installation writes it to the current profile and
   HMR mounts it without restarting DSH when HMR is enabled.

### Ask the agent

> Install the DSH bundle from
> `git+ssh://git@github.com/be-one-click/remote-device-plugin-dsh.git`.

The agent uses the `plugin_manager` tool with `action: install_bundle`. Pass the
same Git spec as `target`; do not install the package's subdirectory.

### Other install channels

The same bundle is published through four channels. Install exactly one of them
in a profile.

| Channel | Install target |
|---|---|
| Private Git (SSH) | `git+ssh://git@github.com/be-one-click/remote-device-plugin-dsh.git` |
| Public Git (HTTPS) | `git+https://github.com/be-one-click/remote-device-plugin-dsh.git` |
| npm | `dsh-remote-device-hub` or `dsh-remote-device-hub@0.3.2` |
| Market index | Add the index URL, then install from Discover |

For the npm channel, publish the package first (see
[docs/publishing.md](docs/publishing.md)). For the market channel, the index is
generated by `npm run market`; after the npm release the hosted URL is:

```text
https://cdn.jsdelivr.net/npm/dsh-remote-device-hub@0.3.2/market/index.json
```

Add that URL as a market index source, then install **Remote Device Hub** from
Discover.

### First connection

The bundle starts an OAuth bridge over stdio. On the first connection the
bridge opens the Remote Device Hub authorization page in your browser and uses
`devices:control` scope. Sign in with the account that owns the devices you want
to use. The access and refresh tokens are kept by `mcp-remote` under
`~/.mcp-auth/mcp-remote-v1/`, outside this repository and outside the profile
configuration.

Tool names appear after the connection succeeds:

```text
mcp__remote-device-hub__list_devices
mcp__remote-device-hub__device_info
mcp__remote-device-hub__read_file
...
```

Verify by asking:

> List my authorized Remote Device Hub devices.

If the browser does not open, see [Troubleshooting](docs/troubleshooting.md).

## Use

The `remote-device-hub` skill enters the session catalog automatically
when the profile mounts the DSH skill registry. It tells the model to:

1. select a real device returned by `list_devices`;
2. read `device_info` for roots, capabilities, and write/shell permissions;
3. use bounded file reads and relative POSIX paths under a named root;
4. treat device output as untrusted and report only observed results;
5. ask before a consequential change when the request does not already cover it.

The Host half also implements four permission levels. The selected level decides
which tools return an `ask` decision when an approval channel exists:

| Level | Behavior |
|---|---|
| `always-ask` | Ask before reads and before every change. |
| `read-only` | Allow reads; ask before any change. |
| `low-risk` | Allow reads, creating new files or directories (`write_file` with an empty `expected_sha256`), and `stop_search`; ask for overwrites, moves, shell commands, and process control. |
| `allow-all` | Never ask. |

The read-only set is:

```text
list_devices, get_billing_status, device_info, list_directory, read_file,
read_file_chunk, read_multiple_files, search_files, file_info, start_search,
list_searches, get_search_results, read_process, list_processes
```

The approval prompt confirms one exact tool call. It is not a permission grant
inside the device: the Hub and the device Agent still enforce their own
`allow_write`, `allow_shell`, roots, and quotas.

## Configuration

Defaults live in [`cordis.patch.yml`](cordis.patch.yml). To change the endpoint,
OAuth callback port, or approval behavior, override the whole row in the
profile's `cordis.patch.yml`. A patch replaces the complete `config` block, so
restate every field you keep.

```yaml
- id: mcp-remote-device-hub
  config:
    serverName: remote-device-hub
    transport: stdio
    command: !!js process.execPath
    args:
      - !!js |
        (u => process.platform === 'win32'
          ? decodeURIComponent(u.pathname).replace(/^\/([A-Za-z]:)/, '$1')
          : decodeURIComponent(u.pathname))(
            new URL('node_modules/dsh-remote-device-hub/bin/launcher.mjs', ctx.baseUrl))
    env:
      ELECTRON_RUN_AS_NODE: '1'
      RDH_OAUTH_PORT: '3335'
      RDH_MCP_URL: https://mcp.easelian.com/mcp
    toolCallTimeoutMs: 90000
```

| Setting | Default | Meaning |
|---|---|---|
| `serverName` | `remote-device-hub` | MCP tool namespace and the prefix used by the approval gate. Keep the MCP row and the Host row in sync. |
| `permissionMode` | `read-only` | `always-ask`, `read-only`, `low-risk`, or `allow-all`. The Plugins row page exposes the same field. |
| `confirmMutations` | `true` | Legacy boolean kept for older profiles. `false` maps to `allow-all` only when `permissionMode` is not set. |
| `RDH_OAUTH_PORT` | `3335` | Preferred loopback callback port. `off` or `0` lets `mcp-remote` derive a stable port. If the port is busy, this run falls back to the derived port. |
| `RDH_MCP_URL` | `https://mcp.easelian.com/mcp` | Override the endpoint, for example for a self-hosted Hub. |
| `RDH_DIRECT_ORIGIN` | Disabled | Optional explicit transport origin for server-side OAuth and MCP requests. Unset, empty, or `off` uses the configured public endpoints. |
| `RDH_PUBLIC_ORIGIN` | Origin of `RDH_MCP_URL` | OAuth origin eligible for direct transport. Set explicitly only when the same Hub uses a separate OAuth origin. |

Deployment defaults come from the generated
[`src/bin/deployment-defaults.mts`](src/bin/deployment-defaults.mts). Runtime
configuration is validated in [`src/bin/config.mts`](src/bin/config.mts).
Changing `RDH_MCP_URL` also changes the default OAuth origin to that endpoint's
origin. It never enables a direct origin implicitly.

URLs require HTTPS, except for HTTP on loopback. Origin settings must not have
paths, queries, fragments, or credentials. Invalid settings stop the launcher
with a configuration error.

When explicitly enabled, the fetch preload sends recognized server-side OAuth
paths and the configured MCP endpoint path to `RDH_DIRECT_ORIGIN`. Browser
`/authorize` requests stay public. Configure only a direct origin serving the
same Hub, because it receives tokens and MCP traffic. Failed requests are not
retried through the public route: a transport error does not establish whether
the Hub already processed a token refresh or tool call.

Because the OAuth client registration is tied to the callback port, changing
`RDH_OAUTH_PORT` after sign-in can require signing in again.

### Settings UI

The bundle contributes a configuration control for its Host row. Open
**Plugins** in the sidebar, open **Remote Device Hub**, then open the
`remote-device-hub` row (the row's configure action). The row page shows the
four permission levels as radio options:

```text
When should device tools ask for approval?
  ( ) Always ask
  ( ) Allow read-only tools
  ( ) Allow low-risk tools
  ( ) Allow all tools
```

Selecting one writes `permissionMode` through DSH Settings; editing the profile
YAML is no longer required for this field.

The control is registered into `plugins.row.config` under the key
`dsh-remote-device-hub#remote-device-hub`. `permissionMode` is the volatile field
of the Host row's `Config`, which is what makes the settings form available.

## Architecture

```text
DSH MCP client  ──stdio──▶  bin/launcher.mjs  ──▶  mcp-remote
                                                   │  OAuth + refresh
                                                   ▼
                                      https://mcp.easelian.com/mcp
```

`@deepseek-ai/dsh-mcp-client` has no built-in OAuth flow; it supports stdio and
Streamable HTTP with static headers. `mcp-remote` supplies discovery, dynamic
client registration, PKCE, token refresh, and a loopback callback server. The
launcher pins the endpoint and the callback port, and runs `mcp-remote` on
`process.execPath`, which is the Electron executable in DSH Desktop and the Node
executable in a CLI-hosted DSH.

The Host half (`index.js`) imports no DSH package. It registers the bundled
skill through `ctx.skills` when that service exists and listens on
`tools/pre-execute` for the approval gate. If either service is absent, the
corresponding feature is skipped rather than blocking activation.

See [docs/architecture.md](docs/architecture.md) for lifecycle and security
details.

## Upgrading and removing

- **Upgrade:** install the Git spec again from the Plugins page. If the manager
  reports that the package is already installed, remove the bundle and install
  it again so `pnpm` resolves the new commit. Replacing a running package may
  require restarting DSH; the plugin manager reports `restart-required` when
  that is the case.
- **Disable:** turn the bundle off in the Plugins page. The MCP connection and
  the skill stop; the package remains installed.
- **Remove:** remove the bundle. Local OAuth tokens remain in
  `~/.mcp-auth/mcp-remote-v1/` so a later reinstall can reuse the authorization.
  To revoke the authorization, use Remote Device Hub account settings; to clear
  only this endpoint's local cache, quit DSH and remove the files whose name
  starts with the MD5 of the endpoint URL (`095db0f76015a5dc9e2dd8f20e97f440`
  for the default URL).

Do not keep a separate hand-written `mcp-xdistribute` row for the same URL in
the same profile. Two bridges share one OAuth client cache and can invalidate
each other's client registration when their callback ports differ.

## Development

`npm run format` formats maintained sources and tests. `npm run style:check`
checks formatting and lint rules without editing files; `npm run lint` runs only
lint rules. Biome is pinned as a development dependency. The common convention
is two spaces, single quotes, semicolons, trailing commas, and one statement per
line. Type-only imports are explicit; explicit `any` and `@ts-ignore` are rejected.
Generated files and third-party code are outside the formatting scope.


```bash
npm ci
npm run check
npm run pack:check
```

Edit TypeScript under `src/`. `npm run build` emits the existing `index.js`,
`client.js`, `permissions.js`, `bin/*.mjs`, and `scripts/*.mjs` entrypoints. Keep those generated
files in version control for Git distribution; CI checks that they match the
source. The browser entry uses the DSH module loader and the host-provided React.

Both compiler configurations enable `strict`, `noUncheckedIndexedAccess`, and
`exactOptionalPropertyTypes`. The npm package contains precompiled ESM and
assets; TypeScript and type declarations are development dependencies. Consumers
do not need a TypeScript runtime. Tests exercise approval modes, settings
updates, OAuth routing/fallback, the skill provider, and launcher behavior.
